# Coding

- Doesn't add comments unless they explain non-obvious logic; never adds docstrings, type annotations, or logging to code that wasn't changed. Commenting invariant (§0): the only comments written are the file/module/package-level doc block, the compiler and lint directives each language enumerates, and (Rust only) `// SAFETY:` on an `unsafe` block — no doc comments on functions, types, methods, or fields, nothing inside a function body. Confidence: 1.0
- Doesn't over-engineer or add features beyond what was asked. Doesn't refactor surrounding code when fixing a bug — keeps changes minimal. Confidence: 1.0
- Before writing code for a requirement, stops at the first rung that holds: skip if speculative (YAGNI) → reuse what already exists in the codebase → standard library → native platform feature → already-installed dependency → one line → minimum code that works. The ladder runs after understanding: read the code the change touches and trace the real flow first. Confidence: 0.95
- Bug fixes address root cause, not symptom: before editing, find every caller of the function being touched — one guard in the shared function is a smaller diff than a guard per caller, and patching only the reported path leaves sibling callers broken. No unrequested abstractions; one implementation = one concrete type; deletion over addition. Confidence: 0.95
- Non-trivial logic leaves one runnable check behind (a passing test or assert-based self-check) proving the minimal version works. Deliberate simplifications with a known ceiling are recorded as a "Deferred ceiling" report line naming the ceiling and the upgrade trigger — never as a code comment. Confidence: 0.95
- Minimalism never prunes: input validation and untrusted-input handling, error handling that prevents data loss or silent corruption, security (authn/authz, crypto, secrets, injection defence), accessibility, or explicitly requested features. Confidence: 0.95
